🌿 The Quokka Language 🌿

"If you can read it, you can know what it does."

📖 Chapter 1: Core Philosophy

Welcome to the Quokka Programming Language v0.0 Complete Reference!

Quokka is a dynamically typed interpreted language with Rust-inspired syntax and safety-oriented conventions. It was designed to be as friendly and approachable as the happiest animal on Earth, but with powerful underlying mechanisms like closure support, robust pattern matching, and a dedicated machine learning engine.

Why Quokka?

  • Friendly Syntax: Takes cues from Rust with let, mut, explicit shadowing, and expression-oriented blocks.
  • Safe Error Handling: Embrace Some/None and Ok/Err instead of null pointers and exceptions!
  • First-class Machine Learning: Direct integrations with the Joey Engine to run LLM and LoRA training pipelines right from the language.

🍼 Chapter 2: Variables, Mutability, & Scoping

Immutability by Default

By default, bindings in Quokka are immutable. To make a binding mutable, use the mut keyword.

let greeting = "Hello, World!";
// greeting = "Hi"; // ERROR: Immutable variable

let mut count = 0;
count = count + 1; // VALID

Mutability of Objects

It's important to understand that let prevents rebinding a variable, but does not necessarily freeze the object it references. Built-in functions can mutate reference types like Lists:

let list = range(0, 10);
// list = range(0, 5); // ERROR: Cannot rebind
push(list, 11); // VALID: Object mutated in memory

Shadow Semantics

Quokka allows explicit shadowing in the same scope via the shadow keyword. This replaces the existing binding, hiding its previous type and value.

let x = 5;
shadow x = "five";
println(x); // Prints: five (type changed from Int to String!)

🛡️ Chapter 3: Error Handling (The Pouch)

Quokka completely drops the concept of null and Exceptions, adopting Monadic optionals instead. Because Quokka is dynamically typed, functions don't require explicit return type declarations to use these features.

The ? Operator

For operations that might fail, use the ? postfix operator. It automatically propagates None or Err from the current function.

fn read_number() {
    // If get_input returns None, returns None instantly
    let text = get_input()?;

    // If to_int returns Err, returns Err instantly
    let number = to_int(text)?;

    return Ok(number);
}

🎯 Chapter 4: Pattern Matching

The match expression decomposes structures safely.

Syntax boundaries: The parser currently only supports matching exactly these structural patterns: Some(x), None, Ok(x), Err(x), and _. Commas are required. Literals, ranges (1..10), and guards are not supported.

match status {
    Ok(val) => print("Success! " ++ to_string(val)),
    Err(e) => print("Oh no, an error!"),
    _ => print("Fallback..."),
}

🤖 Chapter 5: The Joey ML Engine

The Joey engine allows users to queue machine learning operations directly in Quokka scripts.

Execution Model

The joey_* built-ins do not perform work immediately. Instead, they act as a queue builder:

  • Functions like joey_train() append JSON instructions to a global memory buffer and return instantly.
  • Argument validation and execution only occur when joey_run() is called.
  • joey_run() executes a Python ML backend synchronously and blocks the script until completion. There is currently no cancellation or progress API.
// 1. Queue operations instantly:
joey_load_model("meta-llama/Llama-3-8B", "4bit");
joey_qlora(16, 32, 0.05);
joey_dataset("quokka_data", "### Prompt: {prompt}\n### Response: {response}", 512);
joey_train(3, 0.0002, 4, 4);
joey_save("./joey_quokka_model");

// 2. Execute synchronously:
joey_run();

(Note: A future object-oriented Builder API is planned to handle validation more robustly.)
